# Hiu-2026 留言板 · 数据库表结构文档

> 版本 v1.0 · 2026-11-24 · 面向后端开发同学
>
> 本文由前端 Mock 层（`js/mock/db.js` + `js/mock/seed.js`）反向整理。
> 当前原型用 **localStorage** 模拟表（前缀 `hmb_v1_`），基础 **11 张表** + GM 审计表 **1 张**，共 **12 张表**（见 §0.1 / §6）。`uploads` 为生产建议表，前端原型不建。
> 后端落地时按下文映射为关系表即可；**字段名、语义、约束保持一致**，前端联调零改动。

## 0. 总览

### 0.1 表清单（基础 11 张 + GM 审计表，共 12 张）

| # | 表名（前端键） | 建议关系表名 | 用途 | 数据量级 |
|---|---|---|---|---|
| 1 | `users` | `users` | 用户账号与隐私开关 | 小 |
| 2 | `messages` | `messages` | 留言主表 | 中 |
| 3 | `comments` | `comments` | 评论/回复（二级树） | 中 |
| 4 | `likes` | `likes` | 点赞关系 | 中 |
| 4b | `favorites` | `favorites` | 收藏关系（帖子 + 评论） | 中 |
| 5 | `sessions` | `sessions` | 会话令牌 + CSRF | 中 |
| 6 | `loginFails` | `login_fails` | 登录失败计数与锁定 | 小 |
| 7 | `rateWindow` | `rate_window` | 发留言限流滑窗 | 中 |
| 8 | `blindboxReplies` | `blindbox_replies` | **盲盒匿名回复真实身份留痕（审计）** | 小 |
| 9 | `settings` | `settings` | 全局配置（敏感词/当前期次/演示开关） | 单行 |
| 10 | `meta` | `meta` | 种子版本与重置时间 | 单行 |
| 11 | — | `uploads` | ⭐ **图片上传记录（头像/封面/文末图，见 §7，本次新增）** | 中 |
| 12 | — | `admin_actions` | **GM 操作审计（只增不改不删，见 §6）** | 中 |

> 前端原型（Mock）不建 `uploads` 表：图片本体存 `localStorage['hmb_v1_media']`，
> 业务字段只存 `localimg://<id>` 引用。`uploads` 表是**生产环境建议**，供对接对象存储时留痕。

### 0.2 实体关系图

```
┌─────────────┐         ┌──────────────┐         ┌──────────────┐
│   users     │◄────────│   messages   │◄────────│   comments   │
│  (作者)     │ owner_id│  (帖子)      │message_id│ (二级评论树) │
└──────┬──────┘         └──────┬───────┘         └──────┬───────┘
       │                       │                        │
       ├──────► sessions       ├──────► likes ◄─────────┤
       ├──────► login_fails    │      (多态目标)         │
       ├──────► rate_window    └──────► blindbox_replies │
       │                                   (审计留痕)    │
       └──────► blindbox_replies.real_owner_id ─────────┘
```

**多态点赞**：`likes.target_id` 既可能是 `messages.resource_id`，也可能是 `comments.resource_id`。建议后端加 `target_type` 字段（`message`|`comment`）区分，或拆两张表。

## 1. 表详情

### 1.1 `users` 用户表

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `id` | number | BIGINT PK AUTO_INCREMENT | — | 内部主键 |
| `account` | string | VARCHAR(20) | UNIQUE, NOT NULL | 手机号（登录账号） |
| `password` | string | VARCHAR(255) | NOT NULL | **PBKDF2/bcrypt 加盐哈希**（Mock 为明文演示） |
| `displayId` | string | CHAR(8) | UNIQUE, NOT NULL | 对外展示 ID，首位非 0 |
| `nickname` | string | VARCHAR(20) | NOT NULL | 当前昵称（注册时随机生成） |
| `avatarEnum` | number | TINYINT | 1~8 | emoji 头像枚举（上传图片头像后的默认回退） |
| `avatarUrl` | string | VARCHAR(512) | 默认 '' | ⭐ 本次新增：上传头像的引用字符串（见 §7）；空 = 用 `avatarEnum` 回退。改资料不影响历史留言快照 |
| `realName` | string | VARCHAR(20) | 可空 | 真实姓名（隐私开关控制展示） |
| `email` | string | VARCHAR(60) | 可空 | 邮箱 |
| `bio` | string | VARCHAR(60) | 默认 '' | 个性签名 |
| `flagName` | boolean | BOOLEAN | 默认 false | 是否公开真实姓名 |
| `flagEmail` | boolean | BOOLEAN | 默认 false | 是否公开邮箱 |
| `flagPhone` | boolean | BOOLEAN | 默认 false | 是否公开手机号 |
| `flagLiked` | boolean | BOOLEAN | 默认 true | 是否允许他人在个人主页看到「我赞过的」；本人恒可见 |
| `flagFavorite` | boolean | BOOLEAN | 默认 true | 是否允许他人在个人主页看到「我收藏的」；本人恒可见 |
| `createdAt` | number | BIGINT | NOT NULL | 注册时间戳(ms) |

**索引**：`UNIQUE(account)`、`UNIQUE(display_id)`
**注意**：昵称与头像在历史留言里以 `nicknameSnapshot` / `avatarEnum` 快照保存，**改资料不影响历史内容**（D-03）。

### 1.2 `messages` 留言主表

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `resourceId` | string | CHAR(36) PK | UNIQUE | 对外资源 ID（UUID） |
| `no` | string | CHAR(8) | — | 卡片展示用随机号 "NO.7f3a9c21" |
| `ownerId` | number | BIGINT FK | → users.id | 作者 |
| `title` | string | VARCHAR(48) | 可空 | 选填标题 |
| `content` | string | TEXT | NOT NULL | 正文：白名单 HTML 排版片段；**去标签后 1~500 字**，标签不计字数（见 API 文档 §0.6）。历史纯文本兼容 |
| `nicknameSnapshot` | string | VARCHAR(20) | NOT NULL | 发帖时昵称快照 |
| `avatarEnum` | number | TINYINT | 1~8 | 发帖时头像快照 |
| `avatarUrlSnapshot` | string | VARCHAR(512) | 默认 '' | ⭐ 本次新增：发帖时头像 URL 快照（见 §7）；空 = 用 `avatarEnum` 回退 |
| `images` | array | JSON | 默认 '[]' | ⭐ 本次新增：文末图引用数组，最多 10 张、按数组顺序在正文末尾渲染（见 §7）；正文 `content` 不含 `img` |
| `coverUrl` | string | VARCHAR(512) | 默认 '' | ⭐ 本次新增：独立封面引用（见 §7），空 / 失效时前端回退头像 |
| `coverFromFirst` | boolean | BOOLEAN | 默认 false | ⭐ 本次新增：`true` = 前端取 `images[0]` 作封面并随图集变化；后端只存开关，**不存派生封面值** |
| `displayId` | string | CHAR(8) | NOT NULL | 发帖时展示 ID 快照 |
| `topicTag` | string | VARCHAR(16) | 可空 | 话题，必须在 TOPICS 白名单 |
| `isPublic` | boolean | BOOLEAN | 默认 true | 可见类型：false = 仅自己可见 |
| `period` | number | INT | NOT NULL | 所属周榜期次（21~24） |
| `createdAt` | number | BIGINT | NOT NULL | 发帖时间戳(ms) |
| `stats.views` | number | INT | 默认 0 | 浏览数 |
| `stats.likes` | number | INT | 默认 0 | 点赞数 |
| `stats.comments` | number | INT | 默认 0 | 评论数 |
| `stats.favorites` | number | INT | 默认 0 | 收藏数（详情页星标按钮 + API-10b 维护） |
| `heatDelta` | number | DECIMAL(5,1) | 默认 0 | 相对上周变动百分比（如 12.4 = +12.4%）；缺失前端显示 0% |
| `weeklyStats` | array | JSON | 可空 | 逐周原始统计 `[{period,stats:{views,likes,comments,favorites},empty?}]`，可存任意期数（如跨 24 期老帖存 24 项）；前端最多画最近 8 期；仅「发布期→本期」有真实统计，发布前期次带 `empty:true`、stats 填 0，前端按 0 画成贴底平线，**不估算、不伪造热度** |
| `heatHistory` | array | JSON | 可空 | 真实热度序列（含 `empty?` 标记），可存任意期数，优先级高于 `weeklyStats`，前端最多取最近 8 期；0 值/未发布期前端**按 0 画贴底平线**，**不估算、不伪造热度** |
| `lastRank` | number | INT | 默认 0 | 上周名次；0 = 无数据，前端显示 `--`，**不得倒推** |
| `peakRank` | number | INT | 默认 0 | 周榜历史最高名次（0 = 无记录），由后端周榜结算写入；前端完整周榜首次上榜可用当前真实名次展示（搜索结果不兜底），不回写 |
| `peakNewRank` | number | INT | 默认 0 | 新帖榜历史最高名次，由后端结算写入；本周新帖前端不显示历史最高 |
| `isNew` | boolean | BOOLEAN | 默认 true | NEW 徽章标记 |
| `edited` | boolean | BOOLEAN | 默认 false | 是否编辑过 |

**索引建议**
```
UNIQUE(resource_id)
INDEX(owner_id)                         -- 我的留言
INDEX(period, is_public)                -- 期次筛选 + 可见过滤
INDEX(is_public, created_at DESC)       -- 全站列表（tab=hot）
INDEX(topic_tag)                        -- 话题筛选（开放项）
```

**⚠️ 不存 `heat`**：折合分由前端实时计算，后端不落库、不返回。
**⚠️ 新增历史字段不新增表**：`weekly_stats` / `heat_history` / `last_rank` 作为 `messages` 列落地；没有任何趋势推算表。`weekly_stats` 存逐周原始 stats（后端原样采集），热度分与折线走向均由前端按同一公式实时折算。
**⚠️ 图片不落正文**：`content` 继续禁止 `img`，图片走 `images` JSON 数组，前端在正文末尾独立渲染（不做图文混排）；`avatar_url_snapshot` 为空时回退 `avatar_enum`。封面由 `cover_from_first` + `cover_url` 两个字段表达，实际取值由前端判定，替换列表卡片头像位。详见 §7。
**统计口径**：`stats` 是**该帖所属期次的新增互动**（非历史累计）；时间修正 `d` 按 `period` 对应周起点算。

### 1.3 `comments` 评论表（二级树）

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `resourceId` | string | CHAR(36) PK | UNIQUE | 评论 ID |
| `messageId` | string | CHAR(36) FK | → messages.resource_id | 所属帖子 |
| `parentId` | string | CHAR(36) | 可空 | 父评论 ID；一级为 null |
| `rootId` | string | CHAR(36) | 可空 | 根评论 ID；一级为 null |
| `depth` | number | TINYINT | 1 或 2 | **最多二级**，三级 → 5003 |
| `ownerId` | number | BIGINT FK | → users.id | 作者（匿名时仅留痕） |
| `authorName` | string | VARCHAR(20) | NOT NULL | 评论时昵称快照；匿名固定「热心同学」 |
| `authorAvatar` | number | TINYINT | 0~8 | 头像快照；匿名 = 0 |
| `authorDisplayId` | string | CHAR(8) | 可空 | 展示 ID；匿名 = "" |
| `atDisplayId` | string | CHAR(8) | 可空 | 被 @ 用户展示 ID（以展示 ID 为准） |
| `atAuthorName` | string | VARCHAR(20) | 可空 | 被 @ 用户昵称 |
| `content` | string | VARCHAR(500) | NOT NULL | 正文 |
| `createdAt` | number | BIGINT | NOT NULL | 时间戳(ms) |
| `likes` | number | INT | 默认 0 | 点赞数 |
| `edited` | boolean | BOOLEAN | 默认 false | 是否编辑 |
| `likedBy` | array | — | — | **Mock 冗余字段，真实系统直接用 likes 表，不需此列** |
| `isAnonymous` | boolean | BOOLEAN | 默认 false | 是否盲盒匿名回复 |

**索引建议**
```
UNIQUE(resource_id)
INDEX(message_id, created_at)     -- 评论树按帖子查询 + 时间正序
INDEX(parent_id)
```

**匿名红线（F9/D-02）**：`isAnonymous=true` 时，输出层强制 `authorName="热心同学"`、`authorAvatar=0`、`authorDisplayId=""`、`isMine=false`。任何接口都不得把 `ownerId` 暴露给前端；个人主页也绝不展示匿名回复归属。

### 1.4 `likes` 点赞关系表

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `userId` | number | BIGINT FK | → users.id | 点赞用户 |
| `targetId` | string | CHAR(36) | NOT NULL | 目标 resourceId（帖子或评论） |
| `targetType` | — | VARCHAR(10) | 建议新增 | `message` / `comment`（前端 Mock 未区分，后端建议加） |

**索引/约束**
```
UNIQUE(user_id, target_id)       -- 幂等核心：同一用户同一目标只能有一条
INDEX(target_id)
```
**幂等语义**：点赞接口收 `idemKey`。重复 key 直接返回当前状态，不重复 +1/-1。建议另建 `idempotency_keys(key, user_id, created_at)` 表或 Redis SETNX 去重。

### 1.4b `favorites` 收藏关系表

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `userId` | number | BIGINT FK | → users.id | 收藏用户 |
| `targetId` | string | CHAR(36) | NOT NULL | 目标 resourceId（帖子或评论） |
| `targetType` | — | VARCHAR(10) | 建议新增 | `message` / `comment` |
| `createdAt` | number | BIGINT | — | 收藏时间（个人主页互动域按目标创建时间倒序展示） |

**索引/约束**
```
UNIQUE(user_id, target_id)   -- 与 likes 同构，但独立成表
INDEX(user_id, created_at)
```

### 1.5 `sessions` 会话表

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `token` | string | VARCHAR(64) PK | UNIQUE | 会话令牌（Mock 48 位十六进制） |
| `userId` | number | BIGINT FK | → users.id | 所属用户 |
| `csrf` | string | VARCHAR(48) | NOT NULL | CSRF Token（Mock 24 位） |
| `lastActive` | number | BIGINT | NOT NULL | 最后活跃时间戳(ms) |

**逻辑**：空闲 >30 分钟 → 会话失效（401）；每次鉴权成功后顺延 `lastActive`；退出即删除该行。

### 1.6 `login_fails` 登录失败计数表

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `phone` | string | VARCHAR(20) PK | — | 手机号（账号） |
| `count` | number | TINYINT | 默认 0 | 连续失败次数 |
| `lockUntil` | number | BIGINT | 默认 0 | 锁定截止时间(ms) |

**逻辑**：失败 +1；`count>=5` → `lockUntil=now+15min` 且 count 归零；登录成功清空该行。

### 1.7 `rate_window` 限流滑窗表

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `userKey` | string | VARCHAR(20) PK | — | `"u" + userId` |
| `timestamps` | array | JSON / 关联表 | — | 10 秒内发留言时间戳数组(ms) |

**逻辑**：同账号 10 秒滑窗 >3 次 → 4002 + 剩余秒数。**仅发留言受限**，评论/回复/盲盒回复只过敏感词。真实系统建议用 Redis `ZSET`（score=时间戳）实现滑窗。

### 1.8 `blindbox_replies` 盲盒留痕表（审计）

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `replyId` | string | CHAR(36) PK | → comments.resource_id | 匿名回复 ID |
| `messageId` | string | CHAR(36) | NOT NULL | 被回复帖子 ID |
| `realOwnerId` | number | BIGINT | NOT NULL | **真实作者 ID** |
| `at` | number | BIGINT | NOT NULL | 留痕时间(ms) |

**⚠️ 安全红线**：此表是**服务端审计专用**，其 `realOwnerId` **永远不得出现在任何 API 响应中**。前端只知道「热心同学」。

**本人自查看法（本次新增）**：`GET /api/zone` 在 `isSelf=true` 时，可按 `real_owner_id = 当前用户` 关联本表 →
`comments.resource_id` 取匿名回复内容 → 原帖摘要，返回 `blindboxMessages`。仅限本人主页；他人主页恒返回空数组。
**不新增表、不新增路由**。

### 1.9 `settings` 全局配置表（单行）

### 1.11 `uploads` 图片上传记录表（⭐ 本次新增，生产建议）

> 前端原型不建此表（图片本体在 `localStorage['hmb_v1_media']`）。此表用于**生产对接对象存储时留痕**：
> 业务字段仍只存引用字符串，本表记录引用 → 存储对象的映射，便于审计、清理孤儿图与迁移。

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `id` | string | CHAR(36) PK | — | 上传记录 ID |
| `ref` | string | VARCHAR(512) | UNIQUE, NOT NULL | 引用串（生产可 = `url`；原型为 `localimg://<id>`） |
| `url` | string | VARCHAR(512) | NOT NULL | 公网可访问地址（CDN/对象存储） |
| `objectKey` | string | VARCHAR(512) | NOT NULL | 对象存储 key，如 `hmb/2026/11/<id>.webp` |
| `uploaderId` | number | BIGINT FK | → users.id | 上传者 |
| `type` | enum | VARCHAR(10) | `avatar`\|`cover`\|`message` | 用途分目录 |
| `mime` | string | VARCHAR(20) | — | `image/jpeg|png|gif|webp` |
| `size` | number | INT | — | 字节数，≤ 5 MB |
| `createdAt` | number | BIGINT | NOT NULL | 上传时间戳(ms) |

**索引建议**：`UNIQUE(ref)`、`INDEX(uploader_id)`、`INDEX(type)`。
**清理策略**：定期扫描 `uploads` 中不被任何 `users.avatar_url` / `messages.cover_url` / `messages.images` 引用的记录（孤儿图），确认后删除对象 + 记录；删除帖子时其 `images` / `cover_url` 引用可回收（见 §7）。

## 2. 常量字典（写入配置表或代码常量）

| 名称 | 值 | 说明 |
|---|---|---|

## 5. 迁移注意事项（避坑清单）

1. **密码**：Mock 是明文（`abc12345`），真实库必须加盐哈希；首次迁移时强制用户重置或用临时哈希。
2. **时间戳单位**：全部是 **毫秒**（JS `Date.now()`），后端用 BIGINT 存，注意与秒级时间戳转换。
3. **`isMine` 是计算字段**：不落库，由 `session.userId == ownerId` 在出口层生成（本次"所有帖子"功能需要）。
4. **不要存 `heat`/`rank`**：前端算分。若后端需要按热度做数据库层分页查询，另建**只读缓存列**并明确由定时任务刷新，且不能改变前端实时计算的展示结果。
5. **`peakRank` 写入**：已改为**只在后端周榜结算时写入**（原子更新，只降不升）；前端只透传，缺失显示 0，不在浏览时用当前名次反写或持久化。完整周榜首次上榜仅用当前真实名次做展示兜底，搜索结果不兜底。
6. **二级评论约束**：`depth CHECK (1,2)` + 应用层校验，双保险。
7. **敏感词/期次配置**：`settings` 单行表，管理后台可改；期次周界是**周日 00:00**，别按 biliboard 的周二 12:00 实现。
8. **级联删除**：删帖子必须同事务删其评论 + 点赞 + 盲盒留痕，避免孤儿数据。
9. **匿名留痕隔离**：`blindbox_replies` 建议独立权限控制，禁止通用 ORM 直接暴露。
10. **种子版本**：前端 `SEED.VERSION=15`（v14 敏感词库扩至 100 词；v15 清空全部演示数据——帖子 / 期次 / 演示用户 / 评论 / 点赞均为空，仅保留敏感词库与头像/话题/表情常量，并已接入真实后端 `api.js`），bump 会清空全部 localStorage。后端不需要这个概念；真实数据一律以后端接口返回为准，**不再有内置演示账号**（GM `admin/admin` 除外，属固定管理账号）。
11. **富文本内容**：`messages.content` 改 `TEXT` 存白名单 HTML；字数/敏感词按去标签后的可见文字校验。旧纯文本无需迁移。
12. **无数据不估算**：`lastRank` / `peakRank` / `peakNewRank` 缺失时前端显示 `--`（完整周榜首次上榜用当前真实名次展示历史最高，搜索结果不兜底，本周新帖不显示历史最高）；折线图最多画 8 周（超过只取最近 8 期，不足前面补 0），一期一个真实点，0 值/未发布期（`empty:true`）按 0 画成贴底平线（不伪造上升、也不留白），全 0 时平线贴底；**任何历史字段都不得由前端推算或落库**，后端按真实统计落库即可。
13. **活跃度称号不建表**：称号的颁发与等级由前端个人主页进入时按公开活跃数据（留言数 / 评论数 / 收到赞 / 加入天数 / 话题数）实时判定，结果只存浏览器 `localStorage`（`hmb_v1_titles`），**后端不新增字段、不新增表、不返回称号字段**。规则表版本号变更即让旧缓存失效；后端数据变化后前端按输入签名自动重算。
14. **图片字段向后兼容（本次新增）**：`users.avatar_url` / `messages.avatar_url_snapshot` 默认 `''`、`messages.images` 默认 `'[]'`；历史行缺列时按空值处理，前端自动回退 emoji 头像、不渲染图片条，无需刷数据。迁移用 `ALTER TABLE ... ADD COLUMN ... DEFAULT` 即可（见 §7.3）。列里只存引用字符串，**不要存 base64/二进制**。
15. **帖子封面字段向后兼容（本次新增）**：`messages.cover_url` 默认 `''`、`messages.cover_from_first` 默认 `FALSE`；历史行缺列按空 / `false` 处理，列表继续显示作者头像，无需刷数据。后端只存引用与开关，`coverFromFirst=true` 时由前端取 `images[0]`，不落派生封面列。

### 6.2 字段详情

#### 6.2.1 `users` 新增字段

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `role` | string | `ENUM('user','admin')` | NOT NULL DEFAULT `'user'` | 角色；仅 `admin` 可见岛内 GM 项 |
| `status` | string | `ENUM('active','banned')` | NOT NULL DEFAULT `'active'` | 封禁状态；封禁时吊销全部会话 |
| `muteUntil` | number | `BIGINT` | NOT NULL DEFAULT `0` | 禁言截止毫秒时间戳；`0`=无禁言；永久=9999 年末 |
| `banReason` | string | `VARCHAR(200)` | DEFAULT `''` | 封禁原因，解封时清空 |
| `mustChangePassword` | boolean | `BOOLEAN` | DEFAULT `FALSE` | 被管理员重置密码后为 true |

**约束**
- `CHECK (id <> 9999 OR role = 'admin')` —— 内置账号永远是管理员；
- 应用层保证至少存在一名 `role='admin' AND status='active'` 的账号；
- `mute_until` 与 `status` 相互独立：解封不自动解禁言，解除禁言不自动解封。

#### 6.2.2 `messages` / `comments` 新增字段

| 字段 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|
| `hidden` | `BOOLEAN` | NOT NULL DEFAULT `FALSE` | GM 软处置。隐藏后从公开列表/搜索/详情/盲盒候选排除；作者本人列表仍可见并带提示 |

`hidden` **不等于** `is_public`：`is_public=false` 是作者自己的私密设置，`hidden=true` 是管理员的处置结果，
两者任一为真即对外不可见。

#### 6.2.3 `admin_actions` 审计表（新增）

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `id` | number | `BIGINT PK AUTO_INCREMENT` | — | 审计序号 |
| `actorId` | number | `BIGINT` | NOT NULL | 操作人 user_id |
| `actorNickname` | string | `VARCHAR(20)` | NOT NULL | 操作时昵称快照（防改名后追溯丢失） |
| `action` | string | `VARCHAR(40)` | NOT NULL | 操作码，见 §2 |
| `targetType` | string | `VARCHAR(16)` | NOT NULL | `user` \| `message` \| `comment` \| `settings` \| `system` |
| `targetId` | string | `VARCHAR(36)` | DEFAULT `''` | 目标 ID（用户为数字转字符串） |
| `detail` | object | `JSON` | DEFAULT `{}` | 操作详情；**只记字段名与状态值，不记密码/邮箱明文** |
| `ip` | string | `VARCHAR(64)` | DEFAULT `''` | 操作来源 IP |
| `createdAt` | number | `BIGINT` | NOT NULL | 操作时间戳(ms) |

**红线**：该表 `INSERT ONLY`；数据库账号对应用户不应具有 `UPDATE/DELETE` 权限；
前端不提供任何删除入口；按 `created_at` 分区/归档，不在业务库里删除。

| 场景 | 规则 |
|---|---|
| 普通用户列表 / 搜索 / 详情 / 盲盒候选 | `hidden=false AND is_public=true` 才可见 |
| 作者本人"我的留言" | `hidden=true` 仍可见，带"已被隐藏"提示 |
| GM 内容列表 | `hidden=true/false` 都可见，带隐藏标记 |
| 匿名盲盒回复 | `hidden` 字段同样适用；但 `blindbox_replies.real_owner_id` **永远不对 GM 以外的接口暴露**，GM 内容列表也不显示真实身份 |
| GM 用户列表 | 可返回完整 account/email；必须写 `user.read_sensitive` 审计 |

### 6.7 迁移注意事项（新增）

1. **默认密码**：`admin/admin` 仅用于联调；生产首启必须改密码或设 `must_change_password=true`。
2. **账号字段语义变化**：`account` 原本只允许 11 位手机号，`admin` 是唯一例外；所有按手机号格式校验的地方都要加白名单分支。
3. **角色快照**：`users.role` 存当前角色；会话不缓存角色，每次请求读库或用短 TTL 缓存，避免降级后仍有权。
4. **封禁要吊销会话**：`status=banned` 时删除该用户 `sessions` 全部记录，否则旧 token 仍可用。
5. **禁言只拦写操作**：浏览、点赞、查看个人主页不受影响；GM 页不受影响。
6. **隐藏而非删除优先**：先 `hidden=true` 观察，确认无误再物理删除；删除必须事务级联清理 likes/comments/blindbox_replies。
7. **审计只增不改**：不要给应用账号 `UPDATE/DELETE` 权限；归档用分区换出，不要在业务库 DELETE。
8. **最少管理员**：迁移脚本执行后校验 `SELECT COUNT(*) FROM users WHERE role='admin' AND status='active' >= 1`。
9. **岛内第五项依赖 session 新字段**：`GET /api/session` 必须返回 `role` 与 `isAdmin`，否则前端 GM 项不渲染。
10. **种子版本**：前端 `SEED.VERSION` 变更即重建 mock 数据（当前 15，v15 已清空演示数据并接入真实后端）；admin 账号（`admin/admin`）为固定管理账号，与种子数据清空无关；真实业务数据以后端返回为准。

## 7. 图片与头像存储方案（⭐ 本次新增）

### 7.1 设计来源：追风杯导播系统

参考 `Tp-director-system`（纯前端导播配置系统）的建模：

- **业务字段只存字符串引用**：如 `theme.backgroundImage`、`logo`、`subjects[].logo` 存的是 URL 字符串，
  **不存二进制**、不把图片塞进 JSON 对象本体。
- **默认回退**：引用缺失/解析失败回退到默认图（`/favicon.svg`），不报错、不阻塞渲染。
- **向前兼容**：`normalize()` 用默认对象打底 + 深合并，旧数据缺字段也能正常渲染。
- 该系统无后端、无上传接口、无数据库，图片来自预置资源或外部 URL。

本站是前后端分离项目，**沿用「字段存字符串引用 + 失效回退」的核心约定**，并补齐上传接口 U1 与 `uploads` 留痕表（生产环境）。

### 7.2 本站落地（两层）

| 层 | 头像 | 封面 | 文末图 | 存储位置 |
|---|---|---|---|---|
| 前端原型（Mock，当前实现） | `users.avatarUrl` / `avatarUrlSnapshot` 存 `localimg://<id>` | `messages.coverUrl` 存 `localimg://<id>`，`coverFromFirst` 为布尔开关 | `messages.images[]` 存 `localimg://<id>` 数组 | 本体 dataURL 在 `localStorage['hmb_v1_media']` |
| 生产（建议） | 同上字段存 CDN URL | 同上字段存 CDN URL + 布尔开关 | 同上字段存 CDN URL 数组 | 本体在对象存储，`uploads` 表留痕 |

**关键规则**

1. 业务表（`users` / `messages`）**只存引用字符串/JSON 数组**，`VARCHAR(512)` / `JSON` 足够；**不存 base64、不存 BLOB**。
2. 头像：`avatarUrl` 有值且可解析 → 渲染 `<img>`；否则回退 `avatarEnum` emoji（含上传失败、引用失效、空串三种情况）。
3. 文末图：`images[]` 最多 10 张，按数组顺序在**正文末尾独立区块**渲染；失效引用跳过，其余照常显示；横向滑动但隐藏滚动条（能力保留，视觉无条）。点击图片打开全屏大图（纯前端行为）。
4. 封面：`coverFromFirst=true` 且 `images[0]` 有效时取首图（随图集变化），否则取 `coverUrl`；都没有则列表卡片显示作者头像。封面只替换头像位，不插入正文；点击封面同样打开大图。后端只存引用与开关，**不缓存派生封面**。
5. 正文 `content` **仍禁止 `img`**，不做图文混排；字数/敏感词只按可见文字算，图片不计数。
6. 写入口做校验：类型白名单 `image/jpeg|png|gif|webp`、单张 ≤ 5 MB、封面单张、文末图数组长度 ≤ 10、去重、非法引用丢弃（对应 Mock 的 `sanitizeImages()` / `sanitizeCover()`）。
7. 编辑帖子传 `images` 是**整体替换**（非追加）；历史数据缺字段按 `[]`，封面按 `''` / `false`，不改旧数据。

### 7.3 迁移 SQL（MySQL 8）

```sql
-- 用户头像引用
ALTER TABLE users
  ADD COLUMN avatar_url VARCHAR(512) NOT NULL DEFAULT '' AFTER avatar_enum;

-- 帖子头像快照 + 文末图数组
ALTER TABLE messages
  ADD COLUMN avatar_url_snapshot VARCHAR(512) NOT NULL DEFAULT '' AFTER avatar_enum,
  ADD COLUMN images JSON DEFAULT ('[]') AFTER avatar_url_snapshot,
  ADD COLUMN cover_url VARCHAR(512) NOT NULL DEFAULT '' AFTER images,
  ADD COLUMN cover_from_first BOOLEAN NOT NULL DEFAULT FALSE AFTER cover_url;

-- 上传留痕表（见 §1.11 / §4 DDL）
CREATE TABLE uploads (
  id CHAR(36) PRIMARY KEY,
  ref VARCHAR(512) UNIQUE NOT NULL,
  url VARCHAR(512) NOT NULL,
  object_key VARCHAR(512) NOT NULL,
  uploader_id BIGINT NOT NULL REFERENCES users(id),
  type VARCHAR(10) NOT NULL CHECK (type IN ('avatar','cover','message')),
  mime VARCHAR(20) NOT NULL,
  size INT NOT NULL,
  created_at BIGINT NOT NULL,
  INDEX idx_uploader (uploader_id),
  INDEX idx_type (type)
);
```

> **无需数据回填**：以上新增列都有默认值，历史行自动得到 `''` / `'[]'` / `FALSE`，前端按回退逻辑处理即可。
> 前端原型不使用 `uploads` 表；生产上线的图片本体走对象存储，本表仅用于审计与孤儿图清理。
