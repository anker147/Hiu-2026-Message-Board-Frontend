> 版本 v1.0 · 2026-11-24 · 面向后端开发同学
>

### 0.2 实体关系图

```
┌─────────────┐         ┌──────────────┐         ┌──────────────┐
│   users     │◄────────│   messages   │◄────────│   comments   │
│  (作者)     │ owner_id│  (帖子)      │message_id│ (二级评论树) │

       ├──────► login_fails    │      (多态目标)         │
       ├──────► rate_window    └──────► blindbox_replies │
       │                                   (审计留痕)    │
       └──────► blindbox_replies.real_owner_id ─────────┘
```

**多态点赞**：`likes.target_id` 既可能是 `messages.resource_id`，也可能是 `comments.resource_id`。建议后端加 `target_type` 字段（`message`|`comment`）区分，或拆两张表。

## 1. 表详情

### 1.1 `users` 用户表

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `id` | number | BIGINT PK AUTO_INCREMENT | — | 内部主键 |
| `account` | string | VARCHAR(20) | UNIQUE, NOT NULL | 手机号（登录账号） |
| `password` | string | VARCHAR(255) | NOT NULL | **PBKDF2/bcrypt 加盐哈希**（Mock 为明文演示） |
| `displayId` | string | CHAR(8) | UNIQUE, NOT NULL | 对外展示 ID，首位非 0 |
| `nickname` | string | VARCHAR(20) | NOT NULL | 当前昵称（注册时随机生成） |
| `avatarEnum` | number | TINYINT | 1~8 | emoji 头像枚举 |
| `realName` | string | VARCHAR(20) | 可空 | 真实姓名（隐私开关控制展示） |
| `email` | string | VARCHAR(60) | 可空 | 邮箱 |
| `bio` | string | VARCHAR(60) | 默认 '' | 个性签名 |
| `flagName` | boolean | BOOLEAN | 默认 false | 是否公开真实姓名 |
| `flagEmail` | boolean | BOOLEAN | 默认 false | 是否公开邮箱 |
| `flagPhone` | boolean | BOOLEAN | 默认 false | 是否公开手机号 |
| `createdAt` | number | BIGINT | NOT NULL | 注册时间戳(ms) |

**索引**：`UNIQUE(account)`、`UNIQUE(display_id)`
**注意**：昵称与头像在历史留言里以 `nicknameSnapshot` / `avatarEnum` 快照保存，**改资料不影响历史内容**（D-03）。

### 1.2 `messages` 留言主表

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `resourceId` | string | CHAR(36) PK | UNIQUE | 对外资源 ID（UUID） |
| `no` | string | CHAR(8) | — | 卡片展示用随机号 "NO.7f3a9c21" |
| `ownerId` | number | BIGINT FK | → users.id | 作者 |
| `title` | string | VARCHAR(48) | 可空 | 选填标题 |
| `content` | string | VARCHAR(500) | NOT NULL | 正文 |
| `nicknameSnapshot` | string | VARCHAR(20) | NOT NULL | 发帖时昵称快照 |
| `avatarEnum` | number | TINYINT | 1~8 | 发帖时头像快照 |
| `displayId` | string | CHAR(8) | NOT NULL | 发帖时展示 ID 快照 |
| `topicTag` | string | VARCHAR(16) | 可空 | 话题，必须在 TOPICS 白名单 |
| `isPublic` | boolean | BOOLEAN | 默认 true | 可见类型：false = 仅自己可见 |
| `period` | number | INT | NOT NULL | 所属周榜期次（21~24） |
| `createdAt` | number | BIGINT | NOT NULL | 发帖时间戳(ms) |
| `stats.views` | number | INT | 默认 0 | 浏览数 |
| `stats.likes` | number | INT | 默认 0 | 点赞数 |
| `stats.comments` | number | INT | 默认 0 | 评论数 |
| `stats.favorites` | number | INT | 默认 0 | 收藏数（前端预留，暂无 UI） |
| `heatDelta` | number | DECIMAL(5,1) | 默认 0 | 相对上周变动百分比（如 12.4 = +12.4%） |
| `peakRank` | number | INT | 默认 0 | 周榜历史最高名次（0 = 无记录） |
| `peakNewRank` | number | INT | 默认 0 | 新帖榜历史最高名次 |
| `isNew` | boolean | BOOLEAN | 默认 true | NEW 徽章标记 |
| `edited` | boolean | BOOLEAN | 默认 false | 是否编辑过 |

**索引建议**
```
UNIQUE(resource_id)
INDEX(owner_id)                         -- 我的留言
INDEX(period, is_public)                -- 期次筛选 + 可见过滤
INDEX(is_public, created_at DESC)       -- 全站列表（tab=hot）
INDEX(topic_tag)                        -- 话题筛选（开放项）
```

**⚠️ 不存 `heat`**：折合分由前端实时计算，后端不落库、不返回。
**统计口径**：`stats` 是**该帖所属期次的新增互动**（非历史累计）；时间修正 `d` 按 `period` 对应周起点算。

### 1.3 `comments` 评论表（二级树）

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `resourceId` | string | CHAR(36) PK | UNIQUE | 评论 ID |
| `messageId` | string | CHAR(36) FK | → messages.resource_id | 所属帖子 |
| `parentId` | string | CHAR(36) | 可空 | 父评论 ID；一级为 null |
| `rootId` | string | CHAR(36) | 可空 | 根评论 ID；一级为 null |
| `depth` | number | TINYINT | 1 或 2 | **最多二级**，三级 → 5003 |
| `ownerId` | number | BIGINT FK | → users.id | 作者（匿名时仅留痕） |
| `authorName` | string | VARCHAR(20) | NOT NULL | 评论时昵称快照；匿名固定「热心同学」 |
| `authorAvatar` | number | TINYINT | 0~8 | 头像快照；匿名 = 0 |
| `authorDisplayId` | string | CHAR(8) | 可空 | 展示 ID；匿名 = "" |
| `atDisplayId` | string | CHAR(8) | 可空 | 被 @ 用户展示 ID（以展示 ID 为准） |
| `atAuthorName` | string | VARCHAR(20) | 可空 | 被 @ 用户昵称 |
| `content` | string | VARCHAR(500) | NOT NULL | 正文 |
| `createdAt` | number | BIGINT | NOT NULL | 时间戳(ms) |
| `likes` | number | INT | 默认 0 | 点赞数 |
| `edited` | boolean | BOOLEAN | 默认 false | 是否编辑 |
| `likedBy` | array | — | — | **Mock 冗余字段，真实系统直接用 likes 表，不需此列** |
| `isAnonymous` | boolean | BOOLEAN | 默认 false | 是否盲盒匿名回复 |

**索引建议**
```
UNIQUE(resource_id)
INDEX(message_id, created_at)     -- 评论树按帖子查询 + 时间正序
INDEX(parent_id)
```

**匿名红线（F9/D-02）**：`isAnonymous=true` 时，输出层强制 `authorName="热心同学"`、`authorAvatar=0`、`authorDisplayId=""`、`isMine=false`。任何接口都不得把 `ownerId` 暴露给前端；个人主页也绝不展示匿名回复归属。

### 1.4 `likes` 点赞关系表

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `userId` | number | BIGINT FK | → users.id | 点赞用户 |
| `targetId` | string | CHAR(36) | NOT NULL | 目标 resourceId（帖子或评论） |
| `targetType` | — | VARCHAR(10) | 建议新增 | `message` / `comment`（前端 Mock 未区分，后端建议加） |

**索引/约束**
```
UNIQUE(user_id, target_id)       -- 幂等核心：同一用户同一目标只能有一条
INDEX(target_id)
```
**幂等语义**：点赞接口收 `idemKey`。重复 key 直接返回当前状态，不重复 +1/-1。建议另建 `idempotency_keys(key, user_id, created_at)` 表或 Redis SETNX 去重。

### 1.5 `sessions` 会话表

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `token` | string | VARCHAR(64) PK | UNIQUE | 会话令牌（Mock 48 位十六进制） |
| `userId` | number | BIGINT FK | → users.id | 所属用户 |
| `csrf` | string | VARCHAR(48) | NOT NULL | CSRF Token（Mock 24 位） |
| `lastActive` | number | BIGINT | NOT NULL | 最后活跃时间戳(ms) |

**逻辑**：空闲 >30 分钟 → 会话失效（401）；每次鉴权成功后顺延 `lastActive`；退出即删除该行。

### 1.6 `login_fails` 登录失败计数表

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `phone` | string | VARCHAR(20) PK | — | 手机号（账号） |
| `count` | number | TINYINT | 默认 0 | 连续失败次数 |
| `lockUntil` | number | BIGINT | 默认 0 | 锁定截止时间(ms) |

**逻辑**：失败 +1；`count>=5` → `lockUntil=now+15min` 且 count 归零；登录成功清空该行。

---

### 1.7 `rate_window` 限流滑窗表

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `userKey` | string | VARCHAR(20) PK | — | `"u" + userId` |
| `timestamps` | array | JSON / 关联表 | — | 10 秒内发留言时间戳数组(ms) |

**逻辑**：同账号 10 秒滑窗 >3 次 → 4002 + 剩余秒数。**仅发留言受限**，评论/回复/盲盒回复只过敏感词。真实系统建议用 Redis `ZSET`（score=时间戳）实现滑窗。

### 1.8 `blindbox_replies` 盲盒留痕表（审计）

| 字段 | 前端类型 | 建议 SQL 类型 | 约束 | 说明 |
|---|---|---|---|---|
| `replyId` | string | CHAR(36) PK | → comments.resource_id | 匿名回复 ID |
| `messageId` | string | CHAR(36) | NOT NULL | 被回复帖子 ID |
| `realOwnerId` | number | BIGINT | NOT NULL | **真实作者 ID** |

## 3. 数据脱敏规则（出口层实现，不动存储）

| 字段 | 明文存储 | 出口规则 |
|---|---|---|
| 真实姓名 | `users.realName` | `maskName`：王*（首字 + *，最多 2 个星） |
| 邮箱 | `users.email` | `maskEmail`：`abc***@qq.com`（local≥4 取前 3 + ***） |
| 手机号 | `users.account` | `maskPhone`：`138****5678`（前 3 + **** + 后 4） |

**规则**
1. 脱敏在**出口层**做，存储层保留明文（F6）；
2. 列表/主页只回掩码 + 受 `flagXxx` 开关控制，**开关关闭返回空串**；
3. **唯一明文出口** = `GET /api/profile`（本人）；
4. 前端 Mock 里 `toListMessage()` 是唯一的出口函数，后端对应实现一个统一 serializer。

## 4. 关系型落地建议（DDL 参考）

```sql
-- 核心表（简化示意，字段类型按实际DBMS调整）
CREATE TABLE users (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  account VARCHAR(20) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  display_id CHAR(8) UNIQUE NOT NULL,
  nickname VARCHAR(20) NOT NULL,
  avatar_enum TINYINT NOT NULL DEFAULT 1,
  real_name VARCHAR(20) DEFAULT '',
  email VARCHAR(60) DEFAULT '',
  bio VARCHAR(60) DEFAULT '',
  flag_name BOOLEAN DEFAULT FALSE,
  flag_email BOOLEAN DEFAULT FALSE,
  flag_phone BOOLEAN DEFAULT FALSE,
  created_at BIGINT NOT NULL
);

CREATE TABLE messages (
  resource_id CHAR(36) PRIMARY KEY,
  no CHAR(8) NOT NULL,
  owner_id BIGINT NOT NULL REFERENCES users(id),
  title VARCHAR(48) DEFAULT '',
  content VARCHAR(500) NOT NULL,
  nickname_snapshot VARCHAR(20) NOT NULL,
  avatar_enum TINYINT NOT NULL,
  display_id CHAR(8) NOT NULL,
  topic_tag VARCHAR(16) DEFAULT '',
  is_public BOOLEAN DEFAULT TRUE,
  period INT NOT NULL,
  created_at BIGINT NOT NULL,
  views INT DEFAULT 0,
  likes INT DEFAULT 0,
  comments INT DEFAULT 0,
  favorites INT DEFAULT 0,
  heat_delta DECIMAL(5,1) DEFAULT 0,
  peak_rank INT DEFAULT 0,
  peak_new_rank INT DEFAULT 0,
  is_new BOOLEAN DEFAULT TRUE,
  edited BOOLEAN DEFAULT FALSE,
  INDEX idx_owner (owner_id),
  INDEX idx_period_public (period, is_public),
  INDEX idx_public_time (is_public, created_at DESC)
);

CREATE TABLE comments (
  resource_id CHAR(36) PRIMARY KEY,
  message_id CHAR(36) NOT NULL REFERENCES messages(resource_id),
  parent_id CHAR(36),
  root_id CHAR(36),
  depth TINYINT NOT NULL CHECK (depth IN (1,2)),
  owner_id BIGINT NOT NULL REFERENCES users(id),
  author_name VARCHAR(20) NOT NULL,
  author_avatar TINYINT NOT NULL,
  author_display_id CHAR(8) DEFAULT '',
  at_display_id CHAR(8) DEFAULT '',
  at_author_name VARCHAR(20) DEFAULT '',
  content VARCHAR(500) NOT NULL,
  created_at BIGINT NOT NULL,
  likes INT DEFAULT 0,
  edited BOOLEAN DEFAULT FALSE,
  is_anonymous BOOLEAN DEFAULT FALSE,
  INDEX idx_message_time (message_id, created_at),
  INDEX idx_parent (parent_id)
);

CREATE TABLE likes (
  user_id BIGINT NOT NULL REFERENCES users(id),
  target_id CHAR(36) NOT NULL,
  target_type VARCHAR(10) NOT NULL,   -- 'message' | 'comment'
  PRIMARY KEY (user_id, target_id)
);

CREATE TABLE blindbox_replies (
  reply_id CHAR(36) PRIMARY KEY REFERENCES comments(resource_id),
  message_id CHAR(36) NOT NULL,
  real_owner_id BIGINT NOT NULL,
  at BIGINT NOT NULL
);
-- 其余 sessions / login_fails / rate_window / settings / meta 从简
```

## 5. 迁移注意事项（避坑清单）

1. **密码**：Mock 是明文（`abc12345`），真实库必须加盐哈希；首次迁移时强制用户重置或用临时哈希。
2. **时间戳单位**：全部是 **毫秒**（JS `Date.now()`），后端用 BIGINT 存，注意与秒级时间戳转换。
3. **`isMine` 是计算字段**：不落库，由 `session.userId == ownerId` 在出口层生成（本次"所有帖子"功能需要）。
4. **不要存 `heat`/`rank`**：前端算分。若后端需要按热度做数据库层分页查询，另建**只读缓存列**并明确由定时任务刷新，且不能改变前端实时计算的展示结果。
5. **`peakRank` 写入**：当前前端直写 localStorage。接后端后建议改为后端在列表查询时维护（原子更新，只降不升），前端透传。
6. **二级评论约束**：`depth CHECK (1,2)` + 应用层校验，双保险。
7. **敏感词/期次配置**：`settings` 单行表，管理后台可改；期次周界是**周日 00:00**，别按 biliboard 的周二 12:00 实现。
8. **级联删除**：删帖子必须同事务删其评论 + 点赞 + 盲盒留痕，避免孤儿数据。
9. **匿名留痕隔离**：`blindbox_replies` 建议独立权限控制，禁止通用 ORM 直接暴露。
10. **种子版本**：前端 `SEED.VERSION=5`，bump 会清空全部 localStorage。后端不需要这个概念，但**联调时两侧数据要对齐**（演示账号 `13800000001~06` / 密码 `abc12345`）。
