# 文档一：粉粉留言板 PRD（产品需求文档）

**版本**：v1.0　**日期**：2026-11-19　**状态**：开发完成，测试通过

## 1. 项目背景与目标

### 1.1 项目背景
课程原项目 TestJDBC 仅实现了"连接数据库、显示一张表"的基础功能，属于典型的 Web 1.0 演示项目：表单提交整页刷新、提交后跳回页面顶部、没有任何互动玩法。本次改造**不推翻原有 JSP/Servlet 三层架构、不引入任何新框架**，将其升级为一个交互体验对标主流社交产品的"粉粉留言板"，作为 Java Web 课程的综合实训成果。

### 1.2 项目目标
1. **功能闭环**：注册 → 登录 → 留言 → 评论/回复 → 点赞 → 隐私控制 → 退出，全链路可用。
2. **体验目标**：核心操作（提交、点赞、抽盲盒）全部 Ajax 无刷新；提交后原地定位反馈，绝不跳回页面顶部。
3. **工程目标**：严格分层（domain → dao → service → servlet → JSP），关键代码 100% 中文注释，可直接用于教学演示与答辩讲解。
4. **零新依赖**：不引入 fastjson/gson 等任何新 jar，JSON 由手写工具类生成，完全兼容老版本 Tomcat 6 + JDK 1.7 环境。

## 2. 目标用户画像

| 维度 | 描述 |
|---|---|
| 主要用户 | 在校大学生（同班同学互访留言、日常互动） |
| 使用场景 | 课余互踩留言、给同学评论回复、点赞互动、抽盲盒破冰 |
| 交互习惯 | 熟悉微信/QQ 式"原地刷新、即时反馈"，无法忍受提交后跳回顶部 |
| 审美偏好 | 粉色系、圆角卡片、emoji 头像，对"可爱风"接受度高 |
| 次要用户 | 任课教师与答辩评委，关注架构分层、代码规范、安全防御 |

## 3. 核心功能需求

| F1 | 手机号注册 | 手机号作为账号，11 位大陆手机号校验；系统自动分配 8 位随机 ID、随机网名，8 选 1 emoji 头像 | 非法手机号前端拦截；注册成功自动进入留言板 |

## 4. 三大创新亮点

1. **盲盒漂流瓶**：首页"抽取今日盲盒"随机抽一条他人的公开留言（`ORDER BY RAND() LIMIT 1`），弹窗展示，可点赞、可"偷偷回复一句"，回复后对方在留言列表正常可见，制造陌生人社交的惊喜感。
2. **敏感词与防刷安全拦截**：Servlet 前置 Filter 安检门——敏感词（加微信、代考、办证、刷单等）命中即拦截并提示文明发言；同一账号 10 秒内重复发留言触发限流并提示剩余秒数；Ajax 请求返回 JSON、普通请求页面弹窗，双通道反馈。
3. **无刷新 Ajax 交互**：点赞、提交留言、评论、回复、抽盲盒全部由原生 XMLHttpRequest 完成，零框架、零新 jar；提交后只局部替换留言列表区域 HTML，并平滑滚动定位到新内容、清空输入框，彻底消灭"提交跳回顶部"的经典痛点。

## 5. 非功能需求

| 类别 | 需求 |
|---|---|
| UI | 粉色系主题（CSS 变量统一管理），圆角卡片、emoji 头像、toast/弹窗体系，移动端响应式 |
| 安全 | PreparedStatement 全量防 SQL 注入；`<c:out>` / textContent 防 XSS；只能修改、删除自己的内容 |
| 性能 | 数据库连接用完即关；评论树一次查询 + 内存拼装；Tomcat 热加载部署，改代码无需重启 |
| 兼容 | 运行于 Tomcat 6.0.41 + JDK 1.7 + MySQL 5.5，不依赖任何前端框架与额外 jar |
| 编码 | 请求、响应、页面、数据库四层统一 UTF-8，中文全链路无乱码 |

# 文档三：TestJDBC 留言板系统项目开发报告

## 1. 项目概述

本项目在课程原有 TestJDBC（仅数据库连接演示）基础上，改造为一个功能完整的"粉粉留言板"社交系统：手机号注册登录、随机网名与头像、带隐私打码开关的留言、两级树状评论、Ajax 无刷新点赞与提交、盲盒漂流瓶、敏感词与防刷安全拦截，共 4 张业务表、17 个 Servlet、1 个安全 Filter。项目在 Tomcat 6.0.41 + JDK 1.7 + MySQL 5.5 的老环境下零新依赖实现全部现代交互，已通过接口测试与浏览器端到端测试。

## 2. 技术架构说明

采用经典 **MVC 分层架构**，全部基于原生 Java Web 技术栈：

```
浏览器 (JSP + JSTL/EL + 原生JS/CSS)
    ↓ HTTP / Ajax + JSON
Servlet 控制层（17个）—— 参数校验、编码、登录鉴权、分支返回
    ↓
Service 业务层 —— 业务规则（随机昵称、点赞切换、级联删除）
    ↓
DAO 数据访问层 —— 原生 JDBC + PreparedStatement
    ↓
MySQL 5.5（mb_user / mb_message / mb_comment / mb_like / mb_comment_like）
```

- **视图层**：JSP + JSTL（`<c:forEach>` 渲染列表、`<c:out>` 防 XSS、`<fmt:formatDate>` 格式化时间）+ EL 表达式；前端零框架，原生 JS 完成头像绘制、菜单、弹窗、Ajax。
- **控制器**：Servlet 统一 doGet 转 doPost、开头设置 UTF-8；Ajax 与普通请求按 `X-Requested-With` 头分流返回 JSON 或重定向。
- **横切面**：SafetyFilter 作为 Servlet 前置"安检门"，敏感词与防刷逻辑与业务代码完全解耦，原有 Servlet 一行未改。
- **数据层**：DAO 仅使用 PreparedStatement；评论树用"一次查询 + 内存拼装"避免 N+1 查询。

## 3. 核心难点与解决方案

### 3.1 用 Ajax 解决"表单提交跳回顶部"的体验痛点
**难点**：留言/评论表单原本是原生提交，浏览器整页跳转重新渲染，用户在页面底部发完回复会被弹回最顶部，体验极差。
**解决**：
1. 前端在 document 捕获阶段统一拦截 submit，`preventDefault()` 阻止整页提交；
2. 用原生 XMLHttpRequest 按 `application/x-www-form-urlencoded` 提交（不用 FormData，因为 Servlet 2.5 的 getParameter 读不到 multipart 参数），并带上 `X-Requested-With` 头；
3. 后端 DAO 插入后用**同一个连接**执行 `SELECT LAST_INSERT_ID()` 取回新记录 id（跨连接会取到 0），随 JSON 返回；
4. 前端收到成功后**只请求并替换 `#listRegion` 一块的 HTML**（DOMParser 解析后局部替换），列表渲染逻辑仍只写在 JSTL 里，JS 不重复拼模板；
5. `scrollIntoView({block:'center', behavior:'smooth'})` 平滑滚动到 `[data-mid]`/`[data-cid]` 标记的新内容并加 1.8 秒粉色高亮；输入框自动清空、复选框复位、昵称保留。
**效果**：提交前后滚动位置基本不变（实测 scrollY 2033 → 1983，目标元素居中），盲盒"偷偷回复"提交后自动关弹窗并定位。

### 3.2 用 Filter 实现"敏感词 + 防刷"双通道安全拦截
**难点**：要在**不改动任何业务 Servlet** 的前提下，给所有留言/评论入口统一加上安检；并且拦截提示必须同时兼容"整页提交"和"Ajax 提交"两种通道。
**解决**：
1. web.xml 中注册 SafetyFilter，映射 `/AddMessageServlet` 与 `/AddCommentServlet`——请求先过"安检门"再进 Servlet，原有业务代码一行不改，这是 Filter 解耦价值的直接体现；
2. 敏感词数组逐词 `indexOf` 比对内容与昵称，命中即 `return` 不放行 `chain.doFilter`，内容零入库；
3. 防刷限流：Session 记录 lastMessageTime 时间戳，10 秒内重复发留言时计算剩余秒数拦截；
4. 双通道反馈：按 `X-Requested-With` 请求头分支——Ajax 请求直接返回 `{"success":false,"message":...}`，由前端粉色弹窗展示；普通请求写入 session 后重定向回留言板，页面 JS 读取提示后弹窗，一次消费即删除避免反复弹。
**效果**：刷屏、广告类内容全部拦截在入库之前；无论用户走哪种提交方式，都能收到明确、友好的原因提示。

### 3.3 盲盒漂流瓶：一条 SQL 实现随机社交
**难点**：如何在不增加任何新表、新接口的前提下，低成本制造"陌生人社交"的惊喜感。
**解决**：RandomMessageServlet 用 `WHERE user_id<>? AND status=1 ORDER BY RAND() LIMIT 1` 一条 SQL 随机抽一条他人的公开留言，返回 JSON；弹窗内的点赞按钮、"偷偷回复"表单完全复用主列表的 LikeServlet 与 AddCommentServlet（parent_id=0 即一级评论），前端也复用同一套 `applyLikeState` / Ajax 提交函数——新增一个玩法，几乎零重复代码。
**效果**：一个按钮创造破冰场景；"偷偷回复"提交后自动关弹窗并平滑滚动定位到那条留言，对方刷新列表即可看到，闭环自然。

### 3.4 JSTL 时间格式化
**难点**：`<fmt:formatDate>` 在未设置地区时拿不到默认 Locale，页面直接输出 `2026-11-19 15:38:46.0` 这种数据库原始格式，甚至抛格式化异常。
**解决**：在 board.jsp 头部显式声明 `<fmt:setLocale value="zh_CN"/>`，再配合 `pattern="yyyy-MM-dd HH:mm"` 输出友好格式。

### 3.5 其他典型问题
- **编码链**：Java 源码 GBK、JSP UTF-8、请求响应与数据库 characterEncoding 全 UTF-8，中文注释与内容全链路无乱码；
- **编译环境**：JDK 1.7 缺 tools.jar 导致 javac 不可用，改用 ECJ 编译器以 `-source 1.7 -target 1.7` 产出兼容字节码；
- **模板空白**：`white-space: pre-wrap` 会把 JSP 模板里的换行缩进渲染成真实空白，导致回复文字被推到右侧，改写为单行输出解决。

## 4. 测试结论

| 测试项 | 方式 | 结果 |
|---|---|---|
| 接口层 | curl 直接请求各 Servlet，核对 JSON 字段与数据库落库 | 留言/评论/回复/修改/敏感词/防刷全部返回预期 JSON |
| 浏览器端到端 | 无头 Chrome 自动化：登录→发评论→回复→改评论→盲盒回复，逐项断言 | 页面零刷新（全局标记未丢）、新内容居中高亮、输入框清空、无 JS 报错 |
| 热加载部署 | class 与 JSP 直接覆盖 webapps/TestJDBC 后不重启 Tomcat | 新逻辑即时生效，老版本 Tomcat 热加载验证通过 |
| 兼容性 | Chrome 实机 + 移动端宽度（响应式断点 640px） | 布局正常，弹窗、菜单可用 |

结论：功能、体验、安全三类需求全部验收通过，测试期产生的数据已清理，截图归档于 screenshots/ 目录（01~16）。

## 5. AI 辅助开发的个人收获

1. **AI 是"高级结对程序员"而不是代写工具**。真正高效的用法是：我先想清楚需求（例如"提交后不要跳回顶部"），让 AI 给出 2~3 种方案（整页刷新+锚点 / fetch 局部刷新 / DOM 追加），再由我基于项目老环境（Tomcat 6、JDK 7、不能加 jar）做取舍。决策权在我手里，学到的才是我的。
2. **读报错的能力被倒逼着提高了**。本次遇到"javac 找不到主类"、JSTL 时间原样输出、GBK 编码写文件被清空等问题，AI 给出的每一步排查我都要求它先讲原理再动手，反复几次后我已能独立看懂堆栈的第一行。
3. **理解了"分层"和"解耦"不是背书上的名词**。SafetyFilter 一行业务代码不改就给全部留言入口加上了安检；DAO 返回值从 void 改成 int 时，Service、Servlet 逐层跟着变——每层的职责边界在改动中变得具体。
4. **学会了对 AI 的产出保持验收意识**。AI 说"已完成"不等于完成：本次多次用 curl 和浏览器自动化实测，抓到过"高亮动画在 JS 中没生效""局部刷新后事件未重绑"这类"看起来对"的 bug，全部当场修掉。代码要自己验证过才敢写进报告。
